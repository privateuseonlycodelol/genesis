## 1. Executive Summary & Major Breakthroughs

During the 2026-10-27 research pass, two monumental barriers on the Telia F1 / Vantiva GCNT-X router were completely dismantled:

1. **Rootfs Cryptographic Barrier Eliminated (Plaintext AES Key Leaked):**
   - The unlabeled 64-character hexadecimal string emitted on UART console boot line 598 (`<L598 64-hex string, redacted>`) was definitively proven via Broadcom BCMBCA U-Boot source code (`sdk_test_commands.c`, line 1540) to be the **plaintext 32-byte AES rootfs encryption key** (`/trust/key_image_aes`).
   - Broadcom's BSP debug `printf` directly leaks the raw `dm-crypt` master key on every boot.
   - Any raw dump or image of the encrypted `rootfs2` partition can now be decrypted immediately offline without hardware Root-of-Encryption (ROE) extraction.

2. **Unsigned Arbitrary Firmware Flashing Primitive Verified via LAN Recovery:**
   - The bootloader recovery mechanism (triggered by pressing `b` at the boot prompt `*** Press b to enter BOOT-P ***`) was completely automated and reverse-engineered on macOS using `scripts/f1_bootp_tftp_mac.py`.
   - **Protocol Flow:** U-Boot broadcasts BOOTREQUEST -> macOS replies with BOOTREPLY offering `192.168.1.2` and boot file `GCNT-X` -> U-Boot issues TFTP Read Request (RRQ) -> macOS delivers payload over TFTP with multi-block RFC 1350 chunking.
   - **Parser Constraints Mapped:** U-Boot recovery does **not** accept or expect legacy RBI containers (`bli2`). It expects a Flattened Image Tree (FIT / Devicetree `.itb`, magic `0xd00dfeed`).
   - **Zero Cryptographic Signature Enforcement:** U-Boot's `flash_upgrade_img_bundle` validates SHA-256 hashes of components and checks board compatibility (`compatible = "GCNT-X"`). It enforces **no RSA signature, no vendor certificates, and no encryption envelope** in BOOTP recovery mode!
   - **Live Flashing Acceptance:** Delivering a synthetic FIT bundle generated by `scripts/build_f1_fit_skeleton.py` resulted in `flash_upgrade_img_bundle` executing to completion:
     ```text
     INFO: Image upgrade successfull!!
     ```
     U-Boot updated the NAND UBI metadata volumes (`metadata1` and `metadata2`), committed the new boot sequence, switched the active bank from Bank 2 to Bank 1 (`Setting committed 1 valid 1,2 seq 2,1`), and booted into Bank 1 Linux (`nginx` 200).

## 3. The U-Boot Recovery Architecture (`flash_upgrade_img_bundle`)

In U-Boot 2019.07 on Broadcom BCMBCA, entering BOOTP mode and serving a payload executes `action 3` (`flash_upgrade_img_bundle`).

### Required Device Tree Structure for FIT Bundle:
```dts
/dts-v1/;

/ {
    description = "FIT Image Bundle for GCNT-X";
    #address-cells = <1>;
    compatible = "GCNT-X";

    compatible {
        compatible = "GCNT-X";
    };

    images {
        bootfs {
            description = "Kernel / Bootfs";
            data = /incbin/("bootfs.bin");
            type = "kernel";
            arch = "arm64";
            os = "linux";
            compression = "none";
            load = <0x02000000>;
            entry = <0x02000000>;
            hash-1 {
                algo = "sha256";
            };
        };

        rootfs {
            description = "Root Filesystem (SquashFS)";
            data = /incbin/("rootfs.squashfs");
            type = "filesystem";
            arch = "arm64";
            os = "linux";
            compression = "none";
            hash-1 {
                algo = "sha256";
            };
        };
    };

    configurations {
        default = "config-1";
        config-1 {
            description = "GCNT-X Boot Configuration";
            compatible = "GCNT-X";
            bootfs = "bootfs";
            rootfs = "rootfs";
        };
    };
};
```

### Partition Image Identifiers Searched by U-Boot:
From the UART trace during upgrade:
- `bootfs` (Kernel FIT image)
- `rootfs` (Root filesystem image, written directly to target UBI volume)
- `loader` (Secondary bootloader)
- `rootfs_data` (Overlay / persistent user data)
- `ramfs_rd` (RAM filesystem / initrd)

## 4. Software-Only Tooling Developed in This Pass

### 1. `scripts/f1_bootp_tftp_mac.py`
Native macOS BOOTP responder + RFC 1350 multi-block TFTP server + automated UART watcher.
- **Darwin Socket Scoping (`IP_BOUND_IF`):** Binds strictly to `en10` using `libc.setsockopt(sock.fileno(), IPPROTO_IP, IP_BOUND_IF, struct.pack("I", if_index))`. Completely immune to VPN/Tailscale route hijacking (`utun9`).
- **Automated UART Prompt Trigger:** Monitors `/dev/cu.usbserial-0001` for `*** Press b to enter BOOT-P ***` and transmits `b` within milliseconds of prompt appearance.
- **Dynamic ARP Prime:** Automatically executes `arp -s <offered_ip> <target_mac> ifscope <iface>` to prevent macOS kernel routing drops (`[Errno 65] No route to host`).
- **Multi-Block TFTP Engine:** Supports multi-kilobyte/megabyte file transfers with 512-byte block framing and per-block ACK tracking.

### 2. `scripts/build_f1_fit_skeleton.py`
Pure-Python Flattened Device Tree (FDT) binary synthesizer and reader (`FdtReader`).
- Zero external dependencies (requires no `dtc` compiler or U-Boot `mkimage` binaries).
- Assembles binary FIT blobs (`0xd00dfeed`) with FDT tokens (`FDT_BEGIN_NODE`, `FDT_END_NODE`, `FDT_PROP`, `FDT_END`), memory reservation blocks, and string tables.
- Computes SHA-256 hashes automatically for embedded image components.

### 3. Test Suites
- `scripts/test_f1_bootp_tftp_mac.py`: 9 unit tests verifying BOOTP reply building, socket scoping, TFTP RRQ/DATA/ACK framing, and multiblock packetization.
- `scripts/test_build_f1_fit_skeleton.py`: 5 unit tests validating DTB generation, token alignment, and component hash calculation.
- Run tests: `python3 -m unittest scripts/test_f1_bootp_tftp_mac.py scripts/test_build_f1_fit_skeleton.py` (14/14 pass).

## 5. Path to LAN Root Access (Without Hardware Work)

Since `flash_upgrade_img_bundle` flashes partition images without signature enforcement, gaining root access is a pure software packaging task:

### Step 1: Prepare the Root Filesystem Payload
1. Extract the squashfs root filesystem from an available reference or bank.
2. Modify `/etc/shadow` to set a known root password hash (or blank password).
3. Enable dropbear SSH daemon on LAN interface (`/etc/init.d/dropbear enable` or launch script).
4. Re-pack into `rootfs.squashfs` using `mksquashfs`.

### Step 2: Build the FIT Image
Run the FIT builder to generate `recovery-payload.itb`:
```bash
python3 scripts/build_f1_fit_skeleton.py \
    --rootfs path/to/rootfs.squashfs \
    --output artifacts/firmware/f1-root-payload.itb
```

### Step 3: Flash the Payload via Recovery Server
Run the macOS recovery responder:
```bash
sudo python3 scripts/f1_bootp_tftp_mac.py \
    --iface en10 \
    --payload artifacts/firmware/f1-root-payload.itb \
    --serial /dev/cu.usbserial-0001
```
Power on the router. The script will:
1. Detect `Press b to enter BOOT-P` and send `b`.
2. Answer the BOOTREQUEST from `en10`.
3. Deliver the FIT payload over TFTP.
4. U-Boot will write `rootfs` to the inactive bank, commit UBI metadata, and switch active bank sequence.
5. The router reboots into the modified rootfs.
6. Connect via SSH: `ssh root@192.168.1.1`!
