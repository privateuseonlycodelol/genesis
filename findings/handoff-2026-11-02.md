# Handoff — EFU/OSIK Signature Chain Resolution & Flashing Architecture (2026-11-02)

## 1. Executive Summary

This pass continued the investigation into the **EFU (Engineering Feature Unlock) and OSIK (Operating System Integrity Key)** signature chain using **REA** and **Hopper Disassembler** on `tools/secr/ripdrv.arm.3.4.11-rt19.ko`.

### Key Breakthrough: 2026-10-29 Key Trace Corrected & Resolved (VERIFIED)
- In [efu-info-proc-2026-10-29.md](efu-info-proc-2026-10-29.md), Section 8, the previous agent had concluded that the buffer populated by `EFU_getOSIK` was unused and that the RSA key source was "unknown" or "uninitialised".
- **Resolution (VERIFIED by instruction disassembly and Hopper decompiler):** In `isSignatureValid` (`0x21a8`), the 256-byte buffer populated by `EFU_getOSIK` at `sp + 0x10` is passed directly as `r0` (`arg0`) to `rsa_create_crypto(sp + 0x10, 2, ctx, 0x588)` at `0x228c`. Inside `rsa_create_crypto`, `mp_read_unsigned_bin` loads these 256 bytes into RSA modulus $n$, and `mp_set_int` sets public exponent $e = 65537$ (`0x10001`).
- **Verdict:** OSIK (`RIP_ID_OSIK`, Item `0x0120`) **is** directly and unequivocally the RSA verification key.

## 2. Verified Technical Facts

1. **Tag Format & Verification:**
   - Writing to `/proc/efu/temporal_tag` (mode `0644`) or reading eRIP Item `0x0125` (`RIP_ID_UNLOCK_TAG`) invokes `verifyTag` and `isSignatureValid`.
   - Tags require a minimum of 264 bytes: 256-byte signature + 8-byte bitmask + optional extensions.
   - The signed message is $\mathcal{M} = \text{Serial\_Number} \mathbin{\Vert} \text{Chip\_ID}_{32\text{BE}} \mathbin{\Vert} \text{Bitmask}$.
   - The signature is verified with **RSA-PSS SHA-256** against OSIK.
   - Forging a tag without the private key corresponding to OSIK is mathematically infeasible.

2. **Homeware Userspace Gate vs Broadcom Bootloader:**
   - In Homeware's `platform.sh`:
     ```sh
     if ! signature_checker -b "$1"; then
         if ! grep -q skip_signature_check /proc/efu/allowed; then
             show_error 10 "Signature check failed"
         else
             v "Ignoring invalid signature"
         fi
     fi
     ```
   - Bit 0 of the verified EFU bitmask populates `/proc/efu/allowed` with `skip_signature_check`.
   - **Crucial Separation:** Broadcom U-Boot's low-level recovery flasher (`flash_upgrade_img_bundle`) operates entirely outside this userspace gate and writes raw `bootfs` and `rootfs` volumes via UBI without checking RSA signatures or consulting `/proc/efu` ([f1-uboot-fit-flashing-schema-2026-10-30.md](f1-uboot-fit-flashing-schema-2026-10-30.md)).
