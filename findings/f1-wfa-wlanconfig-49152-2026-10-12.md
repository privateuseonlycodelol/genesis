# WFA WLANConfig on TCP 49152 — surface, peer state, and event plane

Date: 2026-10-12. Target: owned Telia F1 at `192.168.2.1` (GCNT-X / 23.1.b per prior evidence). Scope: `urn:schemas-wifialliance-org:service:WFAWLANConfig:1` on TCP **49152**. Related: [auth-session-and-wps-2026-10-12.md](auth-session-and-wps-2026-10-12.md) (first `GetDeviceInfo`/M1), [management-auth-boundaries-2026-10-12.md](management-auth-boundaries-2026-10-12.md) (description-only boundary at pass time), [wps-upnp-source-boundary.md](wps-upnp-source-boundary.md) (pinned upstream).

## Exploit status

**No demonstrated exploit.** Verified items are **LAN attack surface** and **protocol behavior**: unauthenticated descriptions, SOAP actions, event `SUBSCRIBE`/NOTIFY, `GetDeviceInfo`→M1, `PutMessage` rejections (**400**/**500**/WSC_NACK), and `SetSelectedRegistrar` reaching message handling (**500**) only after `SUBSCRIBE` with a live CALLBACK. Not shown: PIN or PSK recovery, completed WPS enrollment, Wi‑Fi or admin configuration change, code execution, or WAN-side reachability of 49152.

### Peer state after `GetDeviceInfo` (second pass)

**VERIFIED:** one `GetDeviceInfo` returned HTTP **200** / `GetDeviceInfoResponse` with M1 (`message_type` **0x04**). Enrollee nonce was extracted locally (only `enrollee_nonce_sha256` recorded in `summary.json`).

**VERIFIED:** `PutMessage` with a **parseable** WPS TLV shell (Version + **M1** type + **matching** enrollee nonce) while the peer expects M2:

| Stage | HTTP | `errorCode` | Same fault body as no-peer `AA==`? |
|---|---|---|---|
| After `GetDeviceInfo` (peer present) | **500** | **500** | No |
| Follow-up `PutMessage` `AA==` (peer torn down) | **400** | **400** | Yes (byte-identical to surface pass) |

**DERIVED:** the F1 distinguishes **no peer / parse failure** (**400**) from **peer present but WPS processing failure** (**500**), consistent with upstream `wps_upnp_web.c` (`WPS_FAILURE` → no `NewOutMessage`, internal error). Peer cleanup after the 500 is **supported** by the returning 400 on the next one-byte probe.

Driver: `scripts/wfa_wlanconfig_peer_probe.py` — evidence `artifacts/management/wfa-peer-20261012T055955Z/`.

### Event plane `SUBSCRIBE` (third pass)

**VERIFIED** without HTTP authentication:

| Step | Method | HTTP | Result |
|---|---|---|---|
| `SUBSCRIBE` with `NT: upnp:event` only | SUBSCRIBE | **412** | Missing `CALLBACK` (matches UPnP precondition) |
| `SUBSCRIBE` with `NT` + `CALLBACK` to unused high port on LAN client | SUBSCRIBE | **200** | `SID: uuid:…` assigned (SID hash only in summary) |
| `SetSelectedRegistrar` (empty `NewMessage`) **with active subscription** | POST | **501** | Same fault body SHA-256 as pre-subscription attempt (`bba068ef…`) |
| `UNSUBSCRIBE` with returned `SID` | UNSUBSCRIBE | **200** | Subscription removed |

**DERIVED:** event subscription is **LAN-reachable and unauthenticated**, but **does not** by itself satisfy whatever the F1 requires for `SetSelectedRegistrar` (still **501** / unknown ER from this client). **HYPOTHESIS:** shipped `find_er` may differ from the pinned Android snapshot, or ER binding uses additional state beyond a bare `SUBSCRIBE`.

Driver: `scripts/wfa_wlanconfig_event_probe.py` — evidence `artifacts/management/wfa-event-20261012T060046Z/`.

### Cross-cutting

**DERIVED:** no HTTP session or `Authorization` gate on tested 49152 operations from this LAN client. Controls fail on UPnP/WPS semantics, not on the web UI login.

**UNKNOWN:** WAN/guest/IPv6 exposure; whether a valid registrar `NewMessage` would be accepted after subscription; impact of NOTIFY delivery to a listening callback; concurrent peer list limits under repeated `GetDeviceInfo`.

### NOTIFY capture and shell M2 `PutMessage` (fourth pass)

**VERIFIED:** `SUBSCRIBE` with `CALLBACK` pointing at a local HTTP listener received exactly one **NOTIFY** within 8 s (423 bytes, SHA-256 `4090c9c3…`). Headers included `NT: upnp:event` and `SID`. Property names in the XML event payload: `STAStatus`, `APStatus`, `WLANEvent` (numeric status values and `WLANEvent` blob length recorded only in private artifacts).

**VERIFIED:** after `GetDeviceInfo`, `PutMessage` with a **50-byte** synthetic **M2-shaped** TLV (Version, message type **0x05**, matching enrollee nonce, zero registrar nonce) returned HTTP **200** / `PutMessageResponse` — **not** a SOAP fault. Decoded `NewOutMessage` is **66** bytes; message-type attribute **0x0e** (**WSC_NACK** per upstream `wps_defs.h`). A follow-up one-byte `PutMessage` returned **400**, so the peer session was cleared after the NACK exchange (same teardown signature as the earlier **500** path).

**VERIFIED:** `UNSUBSCRIBE` with the assigned `SID` returned **412** when attempted immediately after NOTIFY delivery to a live listener; the canonical `wfa_wlanconfig_event_probe.py` sequence (no listener, `SetSelectedRegistrar` between subscribe and unsubscribe) still achieves **200** unsubscribe in the same session window.

**VERIFIED:** with a live CALLBACK listener, `SetSelectedRegistrar` carrying `NewMessage=AA==` after `SUBSCRIBE` returns HTTP **500** / SOAP `errorCode` **500** (fault SHA-256 `34981391…`), **not** the **501** seen for empty `NewMessage` without registrar context. **DERIVED:** `SUBSCRIBE` from the same LAN client can move the control plane past the “unknown external registrar” gate into message handling that fails later. Driver: `scripts/wfa_wlanconfig_registrar_probe.py`.
